**Bibliotheca** is a full-stack reading-and-review platform built around a community library of titles, user profiles, lightweight moderation, and an installable PWA shell. The repository is split into a Node/Express + PostgreSQL backend under `server/` and a static, browser-only frontend at the project root that searches the Google Books API live and renders it through the small module set in `src/`. Authentication is Google OAuth only (`passport-google-oauth20`), and session state is carried by `jsonwebtoken` as a Bearer token returned in JSON (the Google callback passes it via `?token=`). The PWA is `sw.js` (cache `bibliotheca-v1`, install/activate/fetch), `manifest.webmanifest` (standalone, theme `#2D4475`, icons 192/512 + maskable), `offline.html` (navigation fallback), and `icons/`; every HTML page registers the worker and links the manifest.

The server exposes a REST surface for authentication, the catalogue itself, user-submitted reviews, and an admin/moderation channel for reports (`server/routes/*`). User, Review, and Report Postgres-backed models live in `server/models/`, and the database connection is configured through `server/config/db.js` with `server/schema.sql` applied on boot by `connectDB()`. The catalogue is not a local dump: `server/routes/books.js` proxies `https://www.googleapis.com/books/v1/volumes` via `mapVolume()` and falls back to a Postgres `ILIKE` description cache. Front-end pages (`index.html`, `login.html`, `profile.html`, `admin.html`, `template.html`, `oauth-callback.html`) plus `offline.html` are plain HTML/CSS/JS rather than a framework, styled by six modules in `src/css/` and driven by seven vanilla modules in `src/` (`auth.js`, `nav.js`, `state.js`, `init.js`, `onSearch.js`, `renderBooks.js`, `searchEventHandlers.js`) with Fuse.js re-rank after two characters. The trust-and-safety pipeline (`moderation-notes.md`) runs profanity, duplicate similarity >0.88, gibberish, and burst rate-limit checks and is operated from `admin.html`.

To run the project, install dependencies with `npm install` in `server/`, copy `.env.example` to `.env`, set the Postgres `DATABASE_URL` (Neon pooled, branch `production`), `JWT_SECRET`, `PORT`, Google OAuth credentials and `GOOGLE_BOOKS_API_KEY`, then start the API with `npm start` (the schema applies on boot via `connectDB()`; no manual seed step, though a one-shot `seedLifelikeReports()` populates demo reports). The static client and PWA assets are served automatically by Express via `express.static`, so a single process hosts both halves. Migrated from `bibliotheca-cms` to `Bibliotheca` (`mk-shipping-it/Bibliotheca`); the Neon DB and Render env vars persist across the repo change -- reuse the same Neon project/URI and either re-point the existing Render service's Connected Repository or create a new Render service.
